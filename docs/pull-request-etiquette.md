# Pull Request Etiquette

Keep pull requests small enough to review in one sitting.

## Scope

Each pull request should cover a single logical change. If you find yourself
listing unrelated fixes in the description, split the work into separate pull
requests so each one can be reviewed on its own merits.

## Writing a good description

Explain what changed, why it changed, and how to verify the change. Link the
related issue or ticket so the reviewer can see the context without asking.

## Responding to feedback

Treat review comments as suggestions about the code, not about you. Reply to
every comment, even if only with a brief acknowledgement, and push follow-up
commits rather than rewriting history while a review is open.

## Timeliness

If a pull request sits for more than two working days without an assigned
reviewer, re-request the review or raise it in the team channel.
